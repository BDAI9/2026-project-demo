# 잇플 장소 조회 연동 조사 및 구현 상태

확인일: 2026-11-12. 공식 제휴 API 어댑터의 실서버 호출은 제휴 기관 정보와 허용 IP가 없어 검증하지 못했습니다. 2026-11-12에는 별도 k-skill 프록시를 이용한 개인 단발 조회에서 실제 가맹점 1건을 확인했습니다. 프록시가 캐시 응답을 반환해 이번 요청의 새 upstream 호출 여부는 확인할 수 없습니다.

## 공식 확인 사항

- [BC카드 잇플 가맹점 검색 API 정의서](https://eatpl.dothome.co.kr/api): 개발 `https://dev-api.paybooc.ai/api/mer`, 운영 `https://api.paybooc.ai/api/mer`; 검색은 `POST /v1/search`. 제휴 기관명 `instNm`과 거래추적번호 `trnsTrceNo`가 필수이며 서버 IP 사전 등록이 필요합니다. 검색 조건 `merNm`, `location`, `merTpbuzNm` 중 하나 이상이 필요합니다.
- 거래추적번호는 `{instNm}{YYYYMMDD}{10자리 seq}` 형식입니다. 어댑터는 형식을 확인하지만 순번의 영속적 발급과 중복 방지는 호출하는 서버 책임입니다. 여러 프로세스에서 무작위 번호를 생성하는 것으로 유일성을 보장하지 마세요.
- 응답은 `rspCode`, `rspMessage`, `data`이며 성공 코드는 `00000`입니다. `data`는 최대 100건이고 페이징이 없습니다. 지역은 주소의 부분 일치이므로 반경 검색 결과가 아닙니다. 검색 결과가 100건에 도달했다면 전체 후보를 받았다고 보장할 수 없습니다.
- 응답에는 가맹점명 `merNm`, 주소 `merAddr`, 업종 `merTpbuzNm`, 상세 `merUrl`, 최근 1개월 전국·지역 매출 백분위 `allSaleRnk`·`ccgSaleRnk`, 예상 영업시간 등이 있습니다. 전화번호가 부정확할 수 있고 영업 추정은 실시간 영업 여부와 다를 수 있습니다. 가격·메뉴·재료·알레르기·인원·분위기 충족은 이 정보만으로 추론하지 않습니다.
- 위치 `xaxsVal`·`yaxsVal`은 TM128입니다. 검증된 변환 및 좌표 품질 확인 전에는 WGS84 위도·경도로 간주하지 않으며 거리 계산에 사용하지 않습니다. 현재는 좌표를 비워 둡니다.
- 응답에 별도의 가맹점 ID는 명시되지 않아 유효한 상세 URL을 해시한 내부 식별자를 우선 사용합니다. URL이 없으면 상호·주소 기반 식별자를 사용하며 같은 상호와 주소가 겹치거나 주소가 변경될 수 있어 영구 식별 보장은 없습니다. 상호와 주소가 모두 식별에 부족한 항목은 오류로 처리합니다.
- [공모전 참가 안내](https://edu.bccard.ai/static/contest/apply.html)에 따르면 받은 상세 주소를 변형하지 말고 이용자 브라우저에서 직접 연결해야 하며, 추적 파라미터, 단축 URL, 중간 페이지 등은 집계에서 제외됩니다. 등록 도메인과 실제 유입 출처가 일치해야 합니다. 내부 클릭 수와 공모전의 순 사용자 집계는 다릅니다. 별도 호출 횟수 제한은 없으나 비정상 호출 시 제한될 수 있다고 안내합니다.
- API 정의서는 `eat.pl 잇플 · BC카드 결제 데이터 기반` 출처 표시를 요청합니다. 앱의 실제 결과 화면 구현 시 표시해야 합니다.

## k-skill과 공식 API 구분

[공모전 안내](https://edu.bccard.ai/static/contest/apply.html)는 개인 개발자가 스킬을 통해 잇플을 호출하는 경로도 설명합니다. [k-skill의 잇플 지침](https://github.com/NomaDamas/k-skill/blob/main/bccard-eatpl-search/instruction.md)은 별도의 GET 프록시를 설명하고, 저장소의 [고지](https://github.com/NomaDamas/k-skill/blob/main/bccard-eatpl-search/SKILL.md)는 제3자 공식 제품이 아니며 자동 수집을 개인적·비조직적 조회로 제한한다고 명시합니다. 따라서 모든 공모전 참가자가 직접 기관명과 IP를 등록해야 한다고 단정할 수는 없으며, 팀 서비스에서 해당 스킬·프록시를 사용할 수 있는지는 공모전 운영 측에 확인해야 합니다. 이 프로젝트의 현재 어댑터는 프록시가 아닌 BC카드의 직접 제휴 API를 대상으로 하므로 그 경로에는 기관명과 IP 등록이 필요합니다.

### 개인 단발 테스트 결과

`python -m backend.skill_probe`는 지역·업종으로 프록시를 한 번 조회해 상호, 주소, 유효한 원문 잇플 링크와 캐시 여부를 표시한다. 옵션 예: `python -m backend.skill_probe --location "서울 중구 을지로30길 20" --business-type "카페"`. 2026-11-12에는 HTTP 200, upstream 상태 200, `items` 1건, 캐시 적중으로 확인되었으며 해당 항목의 `merNm`, `merAddr`, `merTpbuzNm`, `merUrl`을 내부 `Place`로 변환했다.

로컬 서버에서 `k-skill 개인 단발 테스트`를 선택해 서울 중구를 검색한 뒤 실제 카페·식당 코스와 각 원문 링크가 화면에 표시되는 것도 확인했다. 이 조회는 캐시 미사용으로 표시됐다. 별도 조회로 얻은 상세 주소를 브라우저에서 열어 잇플 가맹점 페이지를 확인했다. 좌표 변환이 없어 실제 코스 간 거리는 표시되지 않고, 넓은 지역은 100건 상한으로 전체 결과가 아닐 수 있다.

이 프록시 응답은 최상위 `items`, `upstream`, `proxy` 등을 사용한다. 직접 제휴 API의 `rspCode`, `data` 래퍼와 다르므로 그대로 같은 응답으로 취급하면 안 된다. 개인 단발 테스트에는 발급 기관명을 입력하지 않았지만, 팀 프로젝트에서 프록시를 연결·운영할 수 있는지는 공모전 안내와 스킬 제공자의 조건을 확인해야 한다. 로컬 테스트 성공은 팀 프론트 통합, 공모전 집계 또는 직접 제휴 API 검증을 뜻하지는 않는다.

## 어댑터 사용과 제한

`backend.app.providers.eatpl.EatplPlaceProvider` 생성 시 발급받은 기관명을 전달하고 `search(trace_number=..., location=..., business_type=...)`를 호출합니다. 기본 서버는 개발 환경이며 운영 주소는 명시적으로 선택합니다. 기관명과 운영 설정은 비밀 저장소 또는 환경변수로 주입하고 소스에 적지 마세요. 실제 통합 전 고정 IP 등록, 기관명, 거래추적번호 발급기 및 API 응답을 확인해야 합니다.

빈 목록은 API가 성공적으로 반환한 빈 결과입니다. HTTP 401/403, 시간 초과, 네트워크 오류, 실패 코드·잘못된 응답은 별도 예외로 전달하며 샘플 데이터로 자동 대체하지 않습니다. 안전한 `https://web.paybooc.ai/mer/web/profile/…` 상세 주소만 원문 그대로 보관하고 다른 주소는 이동 링크를 비활성화합니다. 알려진 업종만 카페·식당으로 변환하고 모호한 업종은 `unknown`으로 둡니다.

앱 연동 시 서버에서 결과와 기준 입력 버전을 결합해 오래된 결과의 덮어쓰기를 막고, 후보 목록이 잘렸을 가능성과 인증 실패·조회 중 상태를 사용자에게 구분해 보여줘야 합니다.

## 로컬 데이트 화면의 연결

`python -m backend.server`를 실행하고 `http://127.0.0.1:8000/`에서 지역·코스 순서·전체 1인 예산·최대 직선거리를 입력합니다. 실제 모드는 지역을 `location`에 전달해 1회 검색한 다음, 문서에 확인된 업종만 내부 카페·식당으로 분류합니다. API에 전체 식당을 뜻하는 단일 업종값은 없고, 검색은 최대 100건이므로 조건에 맞는 가게가 모두 검색된다는 보장은 없습니다. 100건이면 화면에 안내합니다. 예산과 거리는 API가 지원하는 검색 필드가 아니어서 서버에서 결과를 평가하며, 근거가 없을 때 확인 필요로 남깁니다.

실제 모드의 제휴 기관명은 `EATPL_INSTITUTION`, 환경은 `EATPL_ENV=dev` 또는 `prod`, 거래추적번호 순번 DB는 `EATPL_TRACE_DB`로 서버에서 설정합니다. 순번은 SQLite 트랜잭션으로 증가하며 같은 기관의 모든 호출자가 동일한 DB를 사용해야 합니다. 각자 다른 DB를 쓰는 다중 서버는 번호가 중복될 수 있어 지원하지 않습니다. 링크는 앱 서버를 경유하지 않는 원문 링크이고 `noreferrer`를 적용하지 않습니다. 로컬 데모 출처는 대회에 등록된 배포 도메인이 아니므로 공모전 유입 집계 여부를 이 화면으로 검증할 수 없습니다.
