# 팀 통합본 실행과 확인

이 버전은 각자 만든 기능을 처음 연결해 확인하는 로컬 시험본이다. 단체·데이트 화면에서 조건 해석 초안을 확인한 다음, 확인된 조건으로 후보를 판정하고 데이트에서는 식당·카페·술집 중 서로 다른 두 장소를 조합한다. 개인별로 자기 컴퓨터에서 실행하며, 공유 방·실시간 참여·조건 저장은 아직 없다.

## 실행

Python 3.10 이상을 설치하고 저장소 폴더에서 실행한다. 각자 진행 중인 변경이 있으면 브랜치 전환 전에 보관하거나 커밋한다.

```bash
git fetch origin
git switch dev
git pull --ff-only origin dev
python -m backend.server
```

`http://127.0.0.1:8000/`을 연다. 서버를 종료하려면 실행한 터미널에서 Ctrl+C를 누른다. `python`이 없는 환경에서는 `python3`를 사용한다.

## 함께 확인할 예시

1. **단체:** 샘플 데이터에서 `강남에서 4명, 해산물 제외`를 입력한다. 해석된 지역, 인원, 제외 조건을 원문과 비교하고 직접 수정한 뒤 확인 체크 후 검색한다. 후보별 통과·제외·확인 필요 사유를 살펴본다.
2. **데이트:** 샘플 데이터에서 지역을 `홍대`, 순서를 카페 다음 식당 또는 식당 다음 술집으로 선택해 코스를 확인한다. 표시되는 좌표와 거리는 가상 데이터의 직선거리로, 실제 장소나 도보 거리·시간이 아니다. 현재 코스는 두 장소만 지원한다.
3. **직접 조건 바꾸기:** 예산이나 제외 조건을 바꿔 결과가 달라지는지, 정보가 부족한 항목이 확인 필요로 남는지 확인한다. 예산은 코스 총액이 아닌 장소별 1인 예산이다.

샘플은 강남·홍대의 가상 장소다. 원문 해석은 규칙 기반 초안이므로 조건을 놓칠 수 있다. 예를 들어 `계란 알레르기`가 자동으로 제외 조건에 들어가지 않을 수 있다. 반드시 직접 입력·확인해야 하며, 결과가 알레르기 안전을 보장하지 않는다. 실제 장소의 메뉴·재료·수용 인원·가격 등도 별도 확인이 필요하다.

실제 가맹점은 화면의 `k-skill 개인 단발 테스트`로 조회할 수 있지만, 제공처 캐시가 반환될 수 있고 조건을 검증할 정보가 부족할 수 있다. 테스트 실패 시 샘플로 자동 대체하지 않는다. 공식 직접 API는 별도 발급·접근 허용이 필요하며, k-skill의 팀 서비스 이용 조건도 확인해야 한다. 자세한 내용은 [연동 문서](integration.md)를 참고한다.

## 팀에서 정할 사항

- 프론트 담당: 이 시험 흐름을 기존 화면에 어떻게 반영할지, 조건 수정과 확인 필요·실패·결과 없음 상태를 어떻게 보여 줄지.
- 조건 담당: 알레르기와 부정 표현 누락을 줄이는 범위, 필수 조건과 선호 조건 및 미확인 항목의 표현. 열려 있는 조건 보완 PR도 별도 검토한다.
- 데이터·거리 담당: 장소별 확인 근거, 좌표계 검증 및 직선거리와 실제 이동 거리의 구분.
- 잇플 담당: 실제 응답과 링크, 공식 접근 신청 및 k-skill 사용 조건 확인. 제공하지 않는 가격·재료 등은 충족으로 추정하지 않는다.
- 전체: 첫 테스트 대상, 결과가 없을 때 조건 완화 방식, 공동 방·초대·동기화의 우선순위와 담당을 합의한다.

각자 실행한 환경, 입력한 문장, 기대 결과와 실제 결과, 어려웠던 점을 공유하면 다음 작업을 구체화하기 좋다.
