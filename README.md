# 2026 Project Demo — 함께 고르는 모임 장소

모임을 만들고 **링크를 공유**하면, 참여자들이 각자 선호와 알레르기를 체크하고 그걸 합쳐 **카페·식당·술집**을 추천합니다. 추천된 가게를 누르면 **잇플 상세 페이지**로 이동합니다. (When2meet처럼 링크 하나로 모이는 방식)

## 사용 흐름

1. 첫 화면에서 **모임 만들기** → 모임 링크가 생깁니다.
2. 링크를 공유하면 참여자마다 체크합니다.
   - **지역** (홍대, 성수 … 또는 직접 입력)
   - **카페 / 식당 / 술집** 중 하나 → 고른 것에 맞춰 다음 선택지가 바뀝니다
     - 카페: 커피 맛집, 디저트·케이크, 베이커리 …
     - 식당: 한식, 중식, 일식, 양식 …
     - 술집: 호프·맥주, 이자카야, 와인·칵테일 바 …
   - **1인 예산**, **분위기**(최대 3개), **알레르기**(+ 기타 직접 입력)
3. **모두의 선택**에서 투표 현황을 실시간(5초마다)으로 봅니다.
4. **추천 받기** → 가장 많이 고른 지역·장소로 추천합니다 (직접 바꿀 수 있음).
   - 누구 하나라도 가진 **알레르기 위험이 높은 업종은 제외**합니다.
   - **종류·예산·분위기**는 같은 걸 고른 사람이 많은 가게일수록 위로 올라갑니다.
   - 가게를 누르면 잇플로 이동합니다.

## 실행

Python 3.10 이상, 추가 설치 없음 (표준 라이브러리만 사용).

```bash
python -m moim          # 이 컴퓨터에서만: http://127.0.0.1:8000/
python -m moim --lan    # 같은 와이파이의 친구들도 접속 (터미널에 주소가 표시됨)
python -m pytest -q     # 테스트 (pytest 필요)
```

Windows에서 `--lan`으로 처음 실행하면 방화벽 허용 창이 뜰 수 있어요. '개인 네트워크'를 허용하세요.

## 설정 (`.env`)

`.env.example`을 `.env`로 복사해 채웁니다. `.env`는 git에 올라가지 않습니다. 키를 코드나 채팅에 쓰지 마세요.

| 변수 | 없을 때 | 있을 때 |
| --- | --- | --- |
| `EATPL_INSTITUTION` | 홍대·성수·강남 **가상 가게**(샘플)로 동작 | 잇플 직접 제휴 API로 실제 가맹점 검색 |
| `EATPL_ENV` | 개발 서버 | `prod`면 운영 서버 |
| `OPENROUTER_API_KEY` | 업종 정보로만 추천 (가격대·분위기 추정 없음) | AI가 가게별 가격대·분위기·알레르기 위험 추정 |
| `OPENROUTER_MODEL` | 기본 무료 모델 3개를 순서대로 시도 | 쉼표로 적은 순서대로 시도 |

### 잇플 API
- `POST {dev-api|api}.paybooc.ai/api/mer/v1/search`, 본문 `instNm`(기관명), `trnsTrceNo`(기관명+YYYYMMDD+10자리 순번), `location`, `merTpbuzNm`.
- **서버를 실행하는 컴퓨터의 공인 IP가 잇플에 등록**돼 있어야 합니다. 403이 나면 IP 등록을 확인하세요.
- 거래추적번호 순번은 `moim.sqlite3`에 저장됩니다. 같은 기관명으로 여러 서버를 동시에 돌리면 번호가 겹칠 수 있습니다.
- 잇플 응답에는 **가격·메뉴·재료·분위기가 없습니다.** 그래서 업종(`merTpbuzNm`)으로 종류와 대표 알레르기 위험을 정하고, 나머지는 AI가 가게 이름·업종으로 추정합니다.
- 추천 카드는 잇플 상세 주소(`https://web.paybooc.ai/mer/web/profile/...`)로 바로 연결됩니다. 다른 주소는 막습니다.

### AI 추정의 한계
- 가격대·분위기·알레르기 위험은 **추정값**이라 틀릴 수 있고, 화면에 표시됩니다.
- 알레르기는 업종 규칙과 AI 중 **더 위험한 쪽**을 씁니다. 그래도 안전을 보장하지 않으므로 매장에 직접 확인해야 합니다.
- 무료 모델은 하루 요청 수 제한이 있고 붐비면 다음 모델로 넘어갑니다. 모두 실패하면 업종 정보로만 추천합니다. 같은 가게의 추정은 저장해 두고 다시 쓰기 때문에 요청 수가 줄어듭니다.

## 코드 구조

| 경로 | 내용 |
| --- | --- |
| `moim/options.py` | 선택지 목록과 입력 검증 |
| `moim/store.py` | SQLite: 모임방, 참여자, 거래추적번호, AI 추정 캐시 |
| `moim/eatpl.py` | 잇플 API 클라이언트, 샘플 데이터 |
| `moim/estimate.py` | 업종 규칙 + OpenRouter AI 추정 |
| `moim/recommend.py` | 투표 집계, 알레르기 제외, 선호 점수 |
| `moim/server.py` | HTTP 서버와 API |
| `web/` | 화면 (모임 만들기, 모임방) |
| `tests/test_moim.py` | 테스트 (잇플·OpenRouter는 가짜 서버로) |

## 아직 안 되는 것
- 인터넷 배포: 지금은 한 컴퓨터에서 서버를 켜고 같은 와이파이로 공유합니다.
- 로그인: 이름만으로 참여합니다. 링크를 아는 사람은 누구나 참여할 수 있습니다.
- 여러 곳을 잇는 코스(카페 → 식당 → 술집)는 이번 버전에서 뺐습니다.

## 협업 흐름

1. 작업 브랜치에서 변경 → PR의 **base는 `dev`**
2. 팀원이 확인 후 `dev`에 병합 → 통합 테스트 후 `dev`에서 `main`으로 PR
3. API 키나 개인 비밀값은 저장소에 올리지 않습니다.
